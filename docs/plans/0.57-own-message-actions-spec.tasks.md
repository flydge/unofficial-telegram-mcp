### Review fixes (057) lead decisions

- **Join, do not port the cut points.** The result's touching pieces of one style are joined and compared with the
  caller's spans; where TDLib cut them is not checked. TDLib also cuts at entities it then hides from the result (a
  media timestamp past the media's duration), so a port of `split_entities` against the visible entities would bring
  false unknowns back; joined runs equal to the caller's spans mean every character carries exactly the reviewed
  styles. Overlapping pieces are refused (never TDLib's output). Rejected: comparing with a port of
  `split_entities` only (the hidden cuts above); accepting any merge of overlapping pieces (looser than TDLib).
- **The formatted send takes the styled-edit rule.** Fixing only the split there would leave a style over a link or
  mention unconfirmed, because the check refused the link itself; both now share `exact_styles`, so the documented
  "only entity ordering may differ" becomes ordering, TDLib's touching pieces and Telegram's detected entities.
- **Media timestamps tolerated, not refused at prepare.** Refusing timestamp-like tokens would block every caption or
  styled text with a time such as 10:30. TDLib emits the entity on every kind an edit or a formatted send admits
  (own duration for a video, audio or voice note; a link preview's or the replied message's media otherwise), so it
  is never refused by kind; the bound is checked only where the result carries it (the own duration). Recorded, not
  changed: the stored message then carries a MediaTimestamp, which source content still refuses
  (`hidden_source_content`, "MediaTimestamp remain closed" since 0.51), so that message cannot be edited again with
  these tools.
- **The reservation in the shared skeleton, outside the dialog gate.** Reserving just before `_owner_dialog` and
  holding it until the claim closes the window for every kind without changing the gate's signature (tests replace
  `_owner_dialog`) and without holding the cross-broker dialog lock over the account round trip. The safety
  condition held: receipts, replay, the 0.54 serialization tests (`tests/test_approval_serialization.py`) and the
  loser routing all pass; only the tests that pinned the old two-dialog limit changed. A call that arrives after the
  claim, while the attempt runs, still reads `outcome_unknown` (an attempt is in flight); once it finished, the
  receipt is replayed. Rejected: holding the dialog lock until the claim (it blocks every other draft's dialog for a
  round trip); deletion only (the window is the same for every kind).
- **Found while checking, recorded, not changed** (fixed by review fix 057b). A plain reply or topic text send
  requires the observed message to carry no entities, but TDLib's pending message carries the entities it detects
  in a user's text, so a plain reply or topic send containing a link, mention or hashtag never confirms and reads
  `outcome_unknown` (reproduced with the reducer). It predates 0.57 and is not one of the review's findings; the fix
  is the same shared rule with no styles, for a follow-up.
