# 0.56 — ordered albums (F15b) — implementation spec

**Status:** lead spec, 21.10.2026, written under the owner's standing delegation. Every decision below is a
**lead decision, owner review pending** (see the [completion plan](completion-plan.md)).
**Branch:** `albums-056`, from the 0.55 release candidate.
**Tasks:** [`0.56-albums-spec.tasks.md`](0.56-albums-spec.tasks.md)
**Requirement:** F15b: ordered albums with per-item preview, a closed `sendMessageAlbum` shape, per-item
outcomes, a `partial` status and no whole-album retry.

## 1. One sentence

The owner can send 2–10 of their own artifacts as one ordered album after one dialog that shows every item.
Each item ends `sent`, `failed` or `outcome_unknown` on exact provider evidence, a mixed result is reported
as `partial`, and nothing is ever resent automatically.

## 2. TDLib facts (pinned d1085f9)

- `sendMessageAlbum chat_id topic_id reply_to options input_message_contents` returns `messages` in input
  order.
- Allowed contents are audio, document, photo and video, up to 10 items. Audio and document groups are
  homogeneous, and `show_caption_above_media` must be equal across items.
- All items share one `sending_id` and a negative `media_album_id`. TDLib emits the N `updateNewMessage`
  before the result.
- Real partial outcomes exist:
  - an upload failure fails the whole group;
  - an item the server omits fails alone with a synthesized "Message was not sent";
  - items deleted mid-upload are skipped.
  - TDLib may resend the group itself after a file-reference error.
- Pending sends survive a restart through the message database, so an item can finish after we report
  `outcome_unknown`. This is disclosed, as for single sends.

## 3. Work items

- **Capability `album_send`**, default off, requires `send`. Album items that are videos also require
  `video_send`, so an album never bypasses that capability. A conjunction test pins this.
- **Tools:**
  - `prepare_album_send(chat, items[{artifact_id, caption?}])`
  - `send_prepared_album(draft_id, approved)`
  - `get_album_send_status(draft_id)`

  There are three new tools, so the census goes from 55 to 58. The frozen `get_send_status` schema is left
  untouched, because album status has its own closed model.
- **Items:**
  - 2–10 items, either a mix of photos and videos or documents only. Audio is deferred: there is no audio
    probe or validator yet.
  - Per-item checks: photos through `validate_photo`, videos through `probe_video`, documents with
    `disable_content_type_detection: true`.
  - Captions are plain text through `_safe_caption`. Formatted album captions come in 0.58 at the
    earliest.
  - `show_caption_above_media` is false and nothing is marked as a spoiler.
  - The total size is at most 256 MiB, leaving headroom in the 512 MiB staging pool with quarantine.
  - Duplicate artifact ids are refused.
- **Draft kind `album`** in the 0.57 draft-kind table, marked dedicated. If that table has not landed yet,
  it is in the dedicated set.
  - Each item carries its kind, artifact id, sha256, size, delivered name, caption and facts. One ordered
    digest binds the preview, the dialog and the receipt.
  - The supersede key is the owner, the recipient and the ordered item ids.
  - Like the other dedicated kinds, an album draft is not cancellable and expires on its own.
- **Admission:** every item id is authorized before any other work. A per-item refusal refuses the whole
  draft with one fixed code.
- **Staging:** one `draft_<32hex>` directory per item, grouped under the album handle.
  - This keeps the one-file-per-directory invariant, so single sends are unaffected, and keeps the
    staged-path validator unchanged.
  - Duplicate delivered names are allowed.
  - Item files are retired only when every slot is terminal or expired.
- **Transport:**
  - `sendMessageAlbum` is added to the allowlist and to the generic `_call` refusals.
  - Closed shape: exact keys, `topic_id` and `reply_to` null, the fixed send options plus `sending_id`,
    and 2–10 items from per-kind validators shared with `sendMessage`. Voice notes are excluded.
  - Exactly one attempt; never retried.
- **Observation:**
  - One observation with N slots. Binding comes only from the exact `messages` result: N items, every one
    pending, the same `sending_id`, the same negative `media_album_id`, and content types in input order.
    Any mismatch is a `conflict`, and every slot stays unknown.
  - A slot becomes terminal only through `updateMessageSendSucceeded` or `updateMessageSendFailed` for its
    bound temporary id.
  - Deletion or absence never proves failure.
- **Status:**
  - Per slot: `pending`, `sent` (with message id), `failed` or `outcome_unknown`.
  - Overall:
    - `sent` when every slot is sent;
    - `failed` when every slot failed;
    - `partial` when at least one slot is sent and at least one is not;
    - otherwise `outcome_unknown`.
  - There is never a resend. A repair is a new draft, or a single send for a lone item.
- **Dialog:** one renderer model on the 0.54 dialog.
  - One row per item: kind, delivered name and caption, each under the readable rules.
  - The total size and the recipient.
  - When only the fallback dialog is available, the album refuses with `dialog_unavailable` rather than
    showing a truncated list.
- **0.55 binding:** the album draft id is a new handle kind in the isolation matrix. Item artifacts are
  account-bound, and staging uses the alias root.
- **Budget:** the surface test's total grows by at most 600 characters per added tool. The change is
  recorded in that test.

## 5. Decisions and rejected options

- **A separate album status model.** Widening `get_send_status` would change a frozen 0.52 schema for every
  client.
- **Audio deferred**, because there is no validator. Document-only and photo/video groups cover the
  requirement.
- **No album retry**, because a retry could duplicate the items that were already delivered.
- **One staging directory per item**, so the single-send staging sweep and validator stay unchanged.

## 6. Risks

- Large albums can outlast the 330-second send budget, so `outcome_unknown` will be common for them. The
  response says so, and the status tool reconciles them later.
- How Telegram clients display several captions in one album has not been verified. That is an owner-session
  check.

**Ceiling:** three distinct failed hypotheses on one sub-step ⇒ stop and record.
