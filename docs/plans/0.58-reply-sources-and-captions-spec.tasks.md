## Part 1 — freeze and ladder table (work items 1 and 2)

**Freeze.** `tests/reply_ladder_matrix.py` generated `tests/fixtures/reply_ladder_matrix_0_57.json` once at the
0.57 tip (f2239c4), before any production change. `tests/test_reply_ladder_matrix.py` pins it by sha256 and
compares freshly computed rows byte for byte. The 6,098 rows cover:
- every subset of the eight span families × {text, document, photo, voice note} × the datetime levels (absent,
  plain, relative, absolute, all three);
- sanitizer-rewritten bodies and forum-topic sources;
- CustomEmoji and MediaTimestamp probes, all refused at 0.57;
- the inline v23 TextUrl literals;
- every row of the eight existing reply goldens.

Each row records the version, the capability tuple, `is_media`, `sanitized`, sha256 digests cut to 16 hex
digits of the projection, the display and one fixed text-reply preview, and every forged version in 0..31 that
the stored projection would also accept (none).

**Ladder table.** `src/telegram_search_mcp/reply_source_ladder.py` is the one owner of each family's name,
keyword, capability, entity map, rank, text and media version, overlap exclusivity and inert display, and of
the fixed capability listing order. Version selection, presence, capability tuples, stored-version admission and
the shims' keyword admission all derive from it. The keyword signatures of `formatted_text`, `validate_content`,
`render_formatted_text`, `render_content` and the media `media_content`, `validate_content` and `render_content`
stay as shims over new `*_for(…, admission)` functions. `_boundaries` and `_inert_json_string` stay in
`reply_formatted_sources`.

**Gate.** The full isolated-HOME suite at 85ef050 gave 4118 passed, 0 failed, 0 skipped, 20830 subtests passed in
2216.07s. That is the 0.57 baseline of 4106 plus the 2 matrix and 10 ladder tests.

Lead decisions, owner review pending:
- **Refusals are not frozen by message.** A refused input records only nulls, because refusal messages are
  internal and the broker maps them all to `unavailable`. The media "disagrees" messages merged into one.
- **The stored-version check replaces the per-family caption checks.** A stored media projection validates under
  its top family and every family below it, and its validated caption must select the stored version. This
  replaces the seven per-family checks and the v12/v14 special cases. The keyword shims keep their 0.57 rule:
  each flagged family must be present.
- **The datetime levels are table rows.** Relative and Absolute are rows that refine DateTime by formatting type.
  They share `reply_datetime_targets` and are absent from the listing order.
- **Exclusivity and inert display are table fields.** They are per-family policy, so a new family sets them in
  its row.
- **The media display fails closed on an inert family.** It refuses until it gets the whole-record inert path,
  so giving TextUrl a media version cannot silently sanitize hidden URLs. This is unreachable at 0.57.
- **The preview digest is the text-reply digest only.** The reply-artifact facts move to v2 in part 3, which
  would otherwise change a frozen value that has nothing to do with the ladder.

- Flipped 0.57 probes go into `FLIPS` in `tests/test_reply_ladder_matrix.py`, each with its reason. A flip may only

## Part 2 — new families on the ladder table (work items 3–6 and 9)

**Families.** Three ladder rows, each exclusive and without a 0.57 shim keyword:
- **v24, media TextUrl.** `TEXT_URL.media_version = 24`. A caption with an inert family renders the whole media
  record (caption and media facts) through v23's one inert JSON layer; part 1's fail-closed branch is gone.
- **v25/v26, CustomEmoji** (`reply_custom_emoji_targets`). The id is TDLib's decimal int64 string, 1 to 2^63−1; an
  integer, sign, padding or non-ASCII digit refuses. The covered text is exactly one emoji. The record shows
  `custom_emoji_id`.
- **v28, MediaTimestamp** (`reply_media_timestamp_targets`), captions only, so v27 is reserved. The entity sits on
  one whole timestamp token with that token's value, from 0 to the media's own duration. Only a voice note has a
  duration, so text, documents and photos refuse it.

**Capability order.** `LISTING_ORDER` now starts with media timestamp, custom emoji, then TextUrl, so every
v1–v23 tuple is unchanged. Both capabilities are in `KNOWN_CAPABILITIES` and the `replies` profile only.

**Unchanged surfaces.** Forward and own-message edit admission still refuse CustomEmoji and MediaTimestamp. The
TDLib allowlist equals the 0.57 set exactly, without `getCustomEmojiStickers`. Both are pinned in
`tests/test_reply_families_058.py`, which also runs the production broker over the synthetic transport for one
text and two artifact replies.

**Flips (criterion 4).** 1,926 media TextUrl rows (subset, sanitizer-rewritten and topic sources on documents,
photos and voice notes), the eight decimal-string custom emoji probes and the two voice-note timestamp probes.
Integer ids, timestamps beyond the duration and timestamps outside a voice note stay refused. Six 0.57 test cases
that asserted a TextUrl caption refuses now assert v24; a seventh now keeps a caption past the display bound closed.

Lead decisions, owner review pending:
- **Profile placement.** Both capabilities join `replies`, the profile that already holds every
  `reply_*_targets` and depends on `send`. They are reply conjuncts, not operation gates.
- **The schema fingerprint moves.** `CapabilityName` enumerates `KNOWN_CAPABILITIES` in eleven output schemas, so
  the critic's "new capabilities do not change it" was wrong. The change is listed as
  `0.58-reply-family-capabilities` and the pin moved; a pinned policy needs the installer's rewrite, as in 0.57.
- **Criterion 4 is read together with work item 4.** The custom emoji probes with a decimal-string id over one
  emoji flip to v25/v26, because work item 4 admits exactly that shape. Only integer ids stay refused.
- **A timestamp must match its token.** TDLib creates these entities from the caption text, so the value is
  checked against the 0.57 grammar of TDLib's `find_media_timestamps` as well as the 0–duration range.
- **The duration bound is a parser argument, not a table field.** It comes from the media itself, mirroring
  TDLib's missing duration (-1) for documents and photos.
- **One emoji is a closed local grammar.** One element (a pictograph with at most one skin-tone modifier, a lone
  modifier, a keycap or a two-letter flag) plus at most one trailing VS16. ZWJ and tag sequences never arrive,
  because the visible-text policy refuses their format characters. During development every one of the 2,331
  control-free elements of the pinned TDLib emoji table (`tdutils/td/utils/emoji.cpp`) was admitted; the table is
  not vendored.
- **Custom emoji are not inert.** The id is ASCII digits and the covered emoji goes through the sanitizer. Heavy
  messages hit the 4,096 display bound: at most 27 custom emoji with 19-digit ids in a text, 26 in a caption,
  disclosed in `docs/reference.md`.
- **The inert media record reports `sanitized` for every media string.** A document or voice note with a TextUrl
  therefore always reports it, because `/` in the MIME type is escaped.
- **Budgets.** The shared reply description was shortened to keep the 0.54 total; the skill's reply paragraph was
  compacted to 19,994 bytes.

Seams for part 3:
