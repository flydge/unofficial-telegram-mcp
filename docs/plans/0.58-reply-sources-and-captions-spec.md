# 0.58 — reply-source families and formatted captions (F13 rest) — implementation spec

**Status:** lead spec, 21.10.2026, written under the owner's standing delegation. Every decision below is a
**lead decision, owner review pending** (see the [completion plan](completion-plan.md)).
**Branch:** `reply-families-058`, from the 0.57 release candidate.
**Tasks:** [`0.58-reply-sources-and-captions-spec.tasks.md`](0.58-reply-sources-and-captions-spec.tasks.md)
**Requirement:** F13 rest:
- TextUrl captions;
- CustomEmoji and MediaTimestamp source families;
- formatted captions;
- the reply-source version ladder consolidated before it grows.

## 1. One sentence

Reply sources may contain media TextUrl captions, custom emoji and voice-note timestamps, and outgoing
artifacts may carry styled captions. Each family is behind its own default-off capability, rendered
inertly and verified exactly. The existing projections v1–v23 do not change.

## 2. Work items

1. **Freeze.** Generate a hash-only characterization matrix at the 0.57 tip and pin it by sha256. It records
   the projection, display hash, capability tuple, `is_media`, `sanitized` and preview digest. It covers:
   - every family subset × {text, document, photo, voice note} × the datetime levels;
   - every existing fixture: the v22 TextUrl goldens, the bank-card, email and phone fixtures, and the
     inline v23 literals.
2. **Ladder table, with no behaviour change.** One module owns:
   - each family's name, keyword argument, capability, entity map and rank;
   - its text version and media version;
   - the fixed order in which present families are listed.

   It replaces `select_version`, the presence flags, the per-version capability tuples, the render keyword
   arguments and the media "disagrees" checks. The matrix must match byte for byte.
   - The public keyword signatures stay as shims.
   - The private names that forward sources import stay.
3. **v24, media TextUrl.** Document, photo and voice-note captions under `reply_text_url_targets`. They go
   through the whole-record inert path that text already uses, so URLs are never silently sanitized.
4. **v25/v26, CustomEmoji.** Text and media, under the new capability `reply_custom_emoji_targets`.
   - The id is a decimal string matching `^[1-9][0-9]{0,18}$`, at most 2^63−1. An integer id is refused.
   - The covered text must be one emoji.
   - Messages heavy with custom emoji hit the 4,096 display bound and are refused, which is disclosed.
5. **v28, MediaTimestamp.** Voice-note captions only, under the new capability
   `reply_media_timestamp_targets`.
   - The value runs from 0 to the voice note's duration.
   - v27 is reserved and refused, so parity still decides `is_media`. Text, document and photo stay
     refused.
6. **Capability order.** Each new family's top capability goes right after `formatted`, extending the fixed
   order at the front, so the v1–v23 tuples do not change. Both new capabilities are conjuncts of
   `reply_*_send` and live only in `KNOWN_CAPABILITIES`.
7. **Formatted captions.**
   - **Gate:** the new capability `formatted_caption_send`, in `SEND_DEPENDENT_CAPABILITIES`, so
     `required_capabilities()` stays the single source.
   - **Scope:** the five styles only, on document, photo, voice-note and video captions.
     - `outgoing_entities` is added to the artifact and reply-artifact requests (a listed schema change).
     - The `draft_models` artifact preview gains a digest over the caption and entities.
     - Reply-artifact facts move to v2 and fill the existing `outgoing_entities` slot.
   - **Transport and read-back:**
     - The `tdjson` caption guards accept only the frozen entities.
     - The read-back is exact, and plain artifacts gain a `caption_sha256`.
     - Album items stay plain unless a later spec says otherwise.
8. **Dialog.** Structured rows per hidden payload and style, on the 0.54 renderer. `ReplyTarget` gains no
   new fields, because it feeds output schemas and the preview digest.
9. **Unchanged surfaces.** Forward and edit admission keep refusing CustomEmoji and MediaTimestamp.
   `getCustomEmojiStickers` stays unreachable, and the allowlist equals the 0.57 set.

## 4. Decisions and rejected options

- **No `read` added for the new reply families.** A reply source is always a message the client already
  obtained through a read tool or a retained selection, and the family capability only widens which hidden
  payloads may be shown. This is on the owner sheet, because the general rule says "reveals content →
  read".
- **MediaTimestamp only on voice notes.** TDLib drops timestamps beyond the media duration, and documents
  and photos have none.
- **The ladder is consolidated before it grows.** Three more families on the hand-copied ladder would make
  golden drift likely.

## 5. Risks

- Reordering capabilities breaks goldens. The matrix catches it.
- Real CustomEmoji evidence needs a Premium sender or a boosted group, which is owner decision #7.

**Ceiling:** three distinct failed hypotheses on one sub-step ⇒ stop and record.
