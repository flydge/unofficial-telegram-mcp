### Part 2 (surface) lead decisions, owner review pending

- **Argument names.** The tool takes `recipient` (and `group`, part 1), like every other prepare-send tool;
  section 3's `chat` was shorthand. *Rejected:* `chat`, which only the archive and edit tools use for the chat
  they change.
- **Video conjunction at prepare.** A missing `video_send` is a structured `capability_disabled` result with
  `missing_capabilities` (and `next_action` `enable_capability`), so the client can tell the owner. Before, the
  broker's error reached the client as a bare `unavailable`. The send keeps the shared `error` shape ("request
  rejected before dispatch") and the status its content-free `none`.
- **Unconfirmed items.** `partial` with an unconfirmed item carries `next_action` `check_send_status`, like
  `outcome_unknown`; a settled `partial` carries none. The closed `NextAction` set is unchanged: a new value would
  change the output schema of every tool that has the field. The fixed details name `get_album_send_status`.
- **Dialog layout.** One entry per item: a row with position, kind, delivered name, bytes and facts, then its
  caption as an exact gutter payload, as in every other dialog; then the group, the total and a technical block
  with the album digest, every item's digest and the preview digest.
- **The fallback.** The 0.54 `display dialog` fallback (short summary and a truncation notice) was never
  shipped. An album therefore has exactly one dialog, the scrolling NSAlert with the complete list; any failure
  to show it is `dialog_unavailable` with no second attempt. A test fails if a shorter dialog is ever added.
- **Budget and fixture.** Each new description stays within 600 characters and the 0.54 total grows by 1,800,
  recorded in the surface test. The schema-change fixture `0.56-album-tools` lists the three new tools; no
  existing tool's schema changed.
- **Proxy deadlines.** The inline 30-second operation set became `SHORT_DEADLINE_OPERATIONS` (album prepare and
  status added); the send keeps the whole request timeout (570 s), which covers the broker's 330-second budget.
- **Manifest.** The `forbidden` list now names the album exclusions instead of "video albums".

### Review fixes (056)

Five findings of the part 2 review, each confirmed by two independent verifiers, and one found while checking
the first. Every fix has a failing-first test; unit and synthetic evidence only (no Telegram, no dialog). Full
isolated suite at 7914085: `3727 passed, 18435 subtests passed in 1553.66s (0:25:53)`, 0 failed, 0 skipped.

- Review fix (056, medium/low): album slots bind by (chat, temporary ID). TDLib d1085f9 numbers temporary
  message IDs per chat, so a terminal update for the same temporary ID in another chat froze a bound slot as a
  conflict (or took an early-buffer row and counted as a second end), and the real success was then ignored:
  the item read `outcome_unknown` for good. `_reduce_album` now ignores a terminal update whose message names
  another chat, bound and early alike (never buffered, never a second end); a malformed or mismatched update in
  the album's own chat, or one whose chat cannot be read, is still a conflict. The single-send observation
  already ignored it. Tests: `ObservationTests` in `tests/test_album_send.py` (the `RECIPIENT + 1` case moved
  out of the conflict table: ignored once bound and the later real update confirms the slot; ignored ahead of
  the result, not buffered, not a second end; a single send pinned).
- Review fix (056, low), found while checking the single send: its observation ignored another chat's update,
  but the send and forward wait loops still ended on any `updateMessageSendSucceeded` for the observed
  temporary ID with `outcome_unknown`, though the real confirmation could follow. Both loops now skip an
  update of another chat (the same `other_chat_update` rule); one whose chat cannot be read still ends the
  wait. Tests: `tests/test_tdjson.py` (`test_a_terminal_update_of_another_chat_never_ends_the_wait`),
  `tests/test_forward_send.py` (`test_an_end_of_another_chat_with_the_same_temporary_id_is_not_ours`).
- Review fix (056, low): `retire_staged_document` and `retire_staged_album` took no lock while the sweep
  (under the staging lock) refuses a fresh empty directory, so an album status read retiring items, or a
  finished single send retiring its copy, could make another approved send fail locally after approval. Both
  now take the lock (the sweep calls the unlocked `_retire_locked`), and the sweep skips an entry that
  vanishes while it reads it (`FileNotFoundError`) while every unsafe entry still present is refused as before.
  Tests: `RetirementRaceTests` in `tests/test_outgoing_stage.py` (retirement paused between the copy and its
  directory while another send stages, single and album; four vanishing points; unsafe contents, a fresh empty
  directory and a foreign entry still refused).
- Review fix (056, medium/low): an item whose recorded name exceeds 240 UTF-8 bytes made `album_item` raise a
  plain `ValueError` and the tool answered `unavailable`, the unknown-artifact shape, with no workaround. Lead
  decision applied: each item takes an optional `display_name` with exactly the grammar of
  `prepare_artifact_send`'s; given, it is the delivered name; absent, the recorded name (else the fixed name)

  input. The proxy binds every given name to the preview and the dialog shows the delivered name; the

  `tests/test_album_send.py` (grammar against `PrepareArtifactSendRequest`; a 264-byte Cyrillic recorded name

  codes, proxy binding).
- Review fix (056, low): both copies of the telegram-setup skill listed the enable profiles without `albums`;
