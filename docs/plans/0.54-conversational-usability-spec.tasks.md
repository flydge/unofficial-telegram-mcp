# 0.54 conversational usability — tasks

Spec: [`0.54-conversational-usability-spec.md`](0.54-conversational-usability-spec.md).

- [ ] **A. Surface.** Description budget, titles, annotations, field descriptions, prompts. Gate: criteria 1, 2.
- [ ] **B. Refusals and recovery.** Fixed input refusals, reply-source capability results, `next_action`,
      split `not_approved`. Gate: criteria 3, 4, 5.
- [ ] **C. Approvals.** Renderer, JXA dialog with proof or fallback, lean chat preview. Gate: criterion 6.
      - 21.10, approvals slice (wave 1):
        - One renderer, `approval_prompt.render_approval`, for every kind: plain text, file, topic or
          formatted text, text reply, reply with a file, forward, video, archive and text edit.
        - The document is a summary (action, chat, account, expiry), then the exact payload behind a `│ `
          gutter with real line breaks, then the reading rule, then `Technical details:` (draft ID,
          hashes), then the closing sentence. Rows are at most 96 columns; continuations start with
          `┆ `.
        - The topic, reply and artifact dialogs no longer print raw Telegram text. Plain text and file
          sends now receive their bound `draft_preview`, so they show account, expiry and draft ID too.
        - Reply-artifact previews are now compared with the broker's arguments.
        - `not_approved` is split into `declined` (`approved=false`, or Cancel, each with its own fixed
          detail), `timeout` and `dialog_unavailable`. None sends. The decision is the closed
          `ApprovalDecision`, truthy only for `approved`; `confirm_approved_send` stays a bool
          compatibility path.
        - The six send/apply tools are listed in `tests/fixtures/schema_changes/0.54-approvals.json`.
      - **Dialog proof (criterion 6), 21.10.2026, macOS 26.6.2.** The production `decide_approved_send`
        ran on a synthetic plain-text draft with a 5-second timer. Nobody clicked.
        - From a temporary user LaunchAgent `io.github.flydge.unofficial-telegram-mcp.dialog-proof`:
          - Setup: process type Background, session type Aqua, spawn type background, and an isolated
            HOME under `$TMPDIR`.
          - Result: token `TIMEOUT`, decision `timeout`, 6.3 s.
          - The window server showed one `osascript` window: layer 8, on screen, alpha 1, 772×618
            points. A capture of that window showed the whole document, with `Cancel` highlighted as
            the default.
          - Cleanup: the job was booted out and the plist deleted; `launchctl print` then reported no
            such service.
        - Directly, not from launchd: token `TIMEOUT`, decision `timeout`, 5.3 s. The window facts and
          the capture were the same.
        - Two defects found by the first runs, both fixed before the runs above:
          1. The alert opened off the owner's current Space. A direct run left it inactive, occluded
             and at alpha 0, while the legacy `display dialog` was visible in the same context. Fix:
             `collectionBehavior` canJoinAllSpaces|fullScreenAuxiliary, plus no appear animation.
          2. AppKit gave the button titled "Cancel" the Escape key, so the dialog had no default
             button. Fix: Return is set on Cancel explicitly.
        - Button wiring: scratch copies of the exact production script, each with one in-process
          `performClick:` after 1 s, returned `DECLINED` for Cancel and `APPROVED` for Send. These are
          synthetic clicks; real owner clicks remain an owner row (F).
        - The fallback (`display dialog` with the short summary and a truncation notice) was not needed.
      - Open for wave 4 (skill and server text, other writers):
        - The chat preview drops hashes and draft IDs.
        - `not_approved` becomes `declined`/`timeout`/`dialog_unavailable` in `_INSTRUCTIONS` and the
          skill.
