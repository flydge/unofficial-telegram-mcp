        and sends no `check`: `true`, `false`, or `null` when nothing is recorded, the outcome is unknown or the
        record is an earlier generation's. Without a registry the default broker writes nothing (0.54). The help
        text says exactly this. Tests: `tests/test_account_readiness.py`, `tests/test_account_jobs.py`.
      - Lead decisions, owner review pending. (1) The masked account is the last two digits of the user id:
        the alias is the primary name, and the digits catch a wrong session without showing the id. (2) The
        login check also pins: the helper sees the first authorized `getMe`, which is the rule the broker
        applies. (3) `attempt_outcome` keeps the pinned 0.54 rule for a lost authority (route by client). A
        variant that hid local-failure evidence from the same client under another account was rejected: it
        broke the pinned drift test, and the evidence ("no provider attempt") is content-free. Accepted after
        the 055c review, which found it only nominally owner-aware (`_attempted_send` and `_change_attempted`
        pass `owner=None`): a consumed draft owned by (C, account 7) still answers `outcome_unknown` or its local
        failure to client C after a switch to account 8, where an unknown draft answers nothing. Kept because
        that answer is content-free (no provider evidence, which is replayed only to the original client
        lifecycle and account epoch) and because the alternative, answering like an unknown draft, would let a
        consumed claim read as expired and invite a second send: the 0.54 rule that rule exists to prevent.
        No code change.
        (4) Budget routing reads the last observed account instead of calling `getMe` again: no extra
