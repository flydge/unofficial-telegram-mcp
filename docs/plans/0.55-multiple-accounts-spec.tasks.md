- [x] **B. Registry, grammar, pin.** Gate: criterion 4, **met** (unit and synthetic evidence; no Telegram).
      Full isolated suite at 2f04c71: `3465 passed, 16270 subtests passed`, 0 failed, 0 skipped.
      - Registry: `account_registry.py`. `TelegramSearchMCP-accounts/registry.json`, owner-only, closed schema
        `{"version":1,"aliases":{alias:{"user_id":int|null}},"default_user_id":int|null}`, at most 8 aliases.
        Anything else refuses with `registry_invalid`; an unsafe file or directory (mode, owner, link count,
        symlink) with `registry_unsafe`. Writes are atomic and owner-only (exclusive temporary, fsync, rename,
        directory fsync) under the registry's own lease, bounded to `registry_busy`. Without a registry nothing
        is written and every path is 0.54. Tests: `tests/test_account_registry.py`.
      - Grammar and budgets. `add_alias` checks before any directory exists: the grammar with `default`
        reserved (`alias_invalid`), the macOS 103-byte socket path (`alias_path_too_long`), and
        `mcp__telegram_search_<alias>__<longest tool>` ≤ 64 (`alias_name_too_long`), where the longest tool
        is read from this release's registration. Today every 12-character alias fits. `remove_alias` drops
        the alias and its pin; the registry stays. `AccountPaths.for_alias` admits a named alias only when the
        registry under that home lists it and its socket fits; the default never reads the registry.
      - `--account <alias>` (spec 3B). Launcher: `mcp`, `broker`, `setup`, `resume`, `connect`, `wait`,
        `cancel`, `api-credentials`, `status`. `telegram-search-setup`: every command but `connect-helper`.
        `telegram-search-mcp --account`, `telegram-search-transfer upload|download --account`,
        `telegram-search-broker run --account`. The alias is a closed token, never `default`, checked against
        the registry before any directory is created. An unregistered alias refuses with `alias_unavailable`,
        an unreadable registry with its own code, and nothing is echoed. Without the flag every argv and call
        is the default's. A named proxy carries the alias in `serverInfo.name` (`telegram-search-mcp-<alias>`)
        and one instructions line, checked through the SDK client; the tool schemas are unchanged. A named
        broker's plist argv ends with `--account <alias>` and is recognised as that alias's own. Tests:
        `tests/test_account_arguments.py`.
      - Pin. The broker's account check runs at authorization (the `check` operation and every account read
        behind artifacts and drafts) and before every operation outside a closed exempt set: `health`,
        `release_client`, `check`, and the local-byte `create_local_artifact` and upload family. A new
        operation is checked by default. The first authorized user is pinned for the alias (the default's in
        `default_user_id`). A different user later blocks with `account_mismatch`, a user pinned under another
        alias, the default included, with `account_duplicate`, and an alias removed under a running broker
        with `alias_unavailable`. The refusal is an `AuthorizationBlocked`: `check` answers `blocked`, and
        other operations answer the existing `unavailable`. No wire code or field is added. A session that is
        not authorized pins nothing. The user id is remembered per authorization epoch and never printed,
        logged or returned. Tests: `tests/test_account_pin.py` (fake TDLib clients with different ids,
        direct dispatch and through the socket).
      - Phase A residual lows. Construction goes through `for_alias` only: the generated `__init__`,

        flags every replace outside `config.py`; three replaces of other dataclasses are listed with reasons.
        The runtime sweep unwraps `functools.lru_cache`/`cache` wrappers at any depth and reads function and
        wrapper attributes.
      - Left for C: writing and starting a named alias's broker LaunchAgent (refused until then), the connect

- [x] **C. Broker, connect, dialog.** Gate: criterion 7, **met** (goldens; unit and synthetic evidence: fake
      launchd runners, synthetic homes, patched osascript; no Telegram, launchd or dialog).
      Full isolated suite at 9ef1895: `3514 passed, 16318 subtests passed`, 0 failed, 0 skipped.
      - Broker LaunchAgent per alias. `launch_agent` writes, bootstraps, restores, stops and boots out a named
        alias's broker only under `<service>.a.<alias>.broker`, plist `~/Library/LaunchAgents/<label>.plist`,
        ProgramArguments ending `--account <alias>` in the bundle launcher and the source form. A definition of
        another account at the alias's path is refused and left untouched; two aliases in one launchd domain
        never name each other's labels. `telegram-search-broker install|status|uninstall --account <alias>`.
        The default keeps today's label, plist and bytes (the phase A goldens are unchanged); the named broker
        and connect payloads are literal bytes for a fixture home. Tests: `tests/test_account_jobs.py`.
      - Connect job per alias. `<service>.a.<alias>.connect` runs `connect-helper --account <alias>` (the
        launcher and `telegram-search-setup` admit it); its plist, status file and lock are in the alias's
        `run/`, and the helper runs only as that job (`XPC_SERVICE_NAME`). A named alias's QR page names the
        alias in its title and one header line, in English and Russian, never the account; the default page's
        assets are byte-identical (pinned by hash). Tests: `tests/test_account_jobs.py`,
        `tests/test_account_connect.py`.
      - Login pin. With a registry, `run_connect` asks the authorized session's `getMe` after Ready and applies
        the broker's own pin before the teardown and handoff. New connect status codes: `account_duplicate` (the
        user is pinned under another alias, the default included) and `account_mismatch` (another user than
        the alias's own), both with next_action `review_enrollment_binding_without_resetting`, and
        `alias_unavailable` (`stop_and_report`); a busy registry reports `dependency_unavailable`. A user not
        yet pinned is pinned at login. On a refusal nothing is handed off, the enrollment stays `pending`, and
        the authorized session stays on disk: it is never logged out or deleted automatically
        (`account-remove` moves it aside). Without a registry the default asks no `getMe` (0.54). The setup
        skill and its plugin copy answer the three codes. Tests: `tests/test_account_connect.py`.
      - Dialog (criterion 7). Once a registry exists the broker passes its alias to the owner dialog: the
        heading names it, and every kind's summary carries `Account: <alias> (Telegram account ••NN)` from one
        helper, so the user id no longer reaches the osascript argv. An alias outside the grammar shows no
        dialog. Without a registry the broker's arguments are 0.54's, both dialog scripts hash to the 3d251c9
        bytes, and the per-kind document goldens are unchanged. Tests: `tests/test_account_dialog.py`.
      - Re-login hardening inside one broker. A `scan_` cursor binds the client lifecycle, the broker
        generation and the account it started under; under another account or generation it is refused like
        an unknown cursor and dropped (switching back never resurrects it). `is_owned_*` take a `DraftOwner`,
        and the broker routes a send budget by this client's owner under the account it last observed, with no
        provider read. `attempt_outcome` takes the `DraftOwner` that held the claim and routes only that
        owner's draft; a call that lost the authority to name it passes `None`, and its client alone decides,
        so a consumed claim still never reads as expired. Tests: `tests/test_relogin_hardening.py`.
      - Status. `status --account <alias>` adds `alias`, `loaded` (that alias's broker label) and `authorized`
        (the check: ready `true`, blocked `false`, otherwise `null`); an account refused by the pin answers
        blocked. The launcher adds no default `clients` report to an alias's status. The default's status keeps
        its 0.54 keys. Tests: `tests/test_account_jobs.py`.
      - Lead decisions, owner review pending. (1) The masked account is the last two digits of the user id:

        (4) Budget routing reads the last observed account instead of calling `getMe` again: no extra
        provider call, and every grant still re-reads the account. (5) An alias's status omits the default's
        `clients`.
